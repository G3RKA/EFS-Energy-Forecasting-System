# EFS — Energy Forecasting System

Настольное приложение на C++/Qt для прогнозирования потребления электроэнергии региона в разрезе групп потребителей. Это программная часть курсового проекта по дисциплине «Проектирование программных систем» (ГУАП, 3 курс). Пояснительная записка лежит в репозитории [SUAI-Software-Engineering-Works](https://github.com/G3RKA/SUAI-Software-Engineering-Works).

Приложение работает с базой данных MySQL. Пользователи входят под своими учётными записями, и каждой роли доступен свой набор функций.

## Роли и возможности

**Администратор** — встроенная учётная запись суперадминистратора (см. «Первый вход»):
- настройка подключения к базе данных и проверка соединения;
- создание, редактирование и удаление учётных записей аналитиков и энергетиков;
- журнал аудита с фильтром по дате; хранятся последние 1000 записей, более старые удаляются автоматически;
- выбор событий, которые попадают в журнал аудита: вход и выход, загрузка и изменение данных, включение и отключение прогноза.

**Аналитик** (роль `analyst` в базе):
- загрузка данных о потреблении из CSV с проверкой формата;
- просмотр и редактирование данных по группам потребителей: число потребителей и потребление по часам;
- включение и отключение автоматического прогнозирования;
- просмотр прогноза.

**Энергетик** (роль `energy` в базе):
- просмотр прогноза потребления по группам;
- статус прогнозирования и время до следующего расчёта.

**Общее**
- пароли пользователей хранятся в виде bcrypt-хешей;
- после 4 неудачных попыток входа вход блокируется на 10 минут;
- при потере соединения с базой данных приложение показывает предупреждение.

## Первый вход

В приложение встроена учётная запись суперадминистратора для первичной настройки: подключения к базе данных и создания пользователей. В базе данных она не хранится.

| Логин | Пароль |
|---|---|
| `EFS_IT_SA` | `12345678Hh` |

Это учебная демо-учётная запись. Её логин и bcrypt-хеш пароля заданы в `Config/AppConfig.cpp`.

## Как строится прогноз

Прогноз рассчитывается автоматически в начале каждого часа, пока прогнозирование включено. Для каждой группы потребителей берётся среднее потребление на одного потребителя в истории за тот же час, тот же месяц и тот же день недели. Это среднее умножается на текущее число потребителей в группе, и результат записывается в таблицу прогнозов.

Таймер прогноза работает в отдельном потоке, поэтому интерфейс показывает обратный отсчёт до следующего часа и не зависает во время расчёта.

## Загрузка CSV

Файл должен иметь заголовок и пять столбцов:

```
Group,Date,Hour,Count,Consumption
Office-A,01.01.2024,10,5,100.5
Office-B,02.01.2024,14,12,250.0
```

| Столбец | Значение |
|---|---|
| `Group` | название группы потребителей; новая группа создаётся автоматически |
| `Date` | дата в формате `ДД.ММ.ГГГГ` |
| `Hour` | час от 0 до 23 |
| `Count` | число потребителей, неотрицательное целое |
| `Consumption` | потребление, неотрицательное число |

Файл разбирается в отдельном потоке. При ошибке приложение показывает номер строки, в которой она найдена. В папке `TestFiles/` лежат корректные примеры и набор файлов с типичными ошибками: неверный заголовок, лишние или недостающие столбцы, отрицательные значения, неверная дата или час, пустые строки.

## База данных

Используется MySQL. Имя базы, хост, порт, логин и пароль задаются в окне настроек подключения и сохраняются в `Settings.ini` в локальной папке данных приложения (`%LOCALAPPDATA%\EFS_Project\EFS`).

### Структура таблиц

Скрипта создания базы в репозитории нет. Ниже структура базы данных, которую ожидает приложение.

**`user`** — учётные записи аналитиков и энергетиков

| Столбец | Тип | Описание |
|---|---|---|
| `Login` | `VARCHAR(64)`, первичный ключ | логин |
| `Name` | `VARCHAR(128)` | имя пользователя |
| `Role` | `VARCHAR(16)` | `analyst` или `energy` |
| `Password` | `VARCHAR(60)` | bcrypt-хеш пароля |
| `LastVisit` | `DATETIME`, может быть пустым | время последнего входа |

**`logs`** — журнал аудита

| Столбец | Тип | Описание |
|---|---|---|
| `LogID` | `INT`, автоинкремент, первичный ключ | номер записи |
| `Login` | `VARCHAR(64)` | кто выполнил действие |
| `Action` | `VARCHAR(255)` | описание действия |
| `Date` | `DATE` | дата |
| `Time` | `TIME` | время |

**`consumergroup`** — группы потребителей

| Столбец | Тип | Описание |
|---|---|---|
| `GroupID` | `INT`, автоинкремент, первичный ключ | идентификатор группы |
| `Name` | `VARCHAR(128)`, уникальный | название группы |
| `Amount` | `INT`, по умолчанию 0 | текущее число потребителей |

**`consuptiondata`** — фактическое потребление и **`forecastdata`** — прогноз (одинаковая структура)

| Столбец | Тип | Описание |
|---|---|---|
| `GroupID` | `INT`, внешний ключ на `consumergroup` | группа |
| `Date` | `DATE` | дата |
| `Hour` | `TINYINT` | час, 0–23 |
| `ConsumerAmount` | `INT` | число потребителей |
| `Consuption` | `DOUBLE` | потребление |

Первичный ключ обеих таблиц — `(GroupID, Date, Hour)`.

### Скрипт создания

```sql
CREATE DATABASE efs CHARACTER SET utf8mb4;
USE efs;

CREATE TABLE `user` (
    `Login`     VARCHAR(64)  NOT NULL PRIMARY KEY,
    `Name`      VARCHAR(128) NOT NULL,
    `Role`      VARCHAR(16)  NOT NULL,
    `Password`  VARCHAR(60)  NOT NULL,
    `LastVisit` DATETIME     NULL
);

CREATE TABLE `logs` (
    `LogID`  INT          NOT NULL AUTO_INCREMENT PRIMARY KEY,
    `Login`  VARCHAR(64)  NOT NULL,
    `Action` VARCHAR(255) NOT NULL,
    `Date`   DATE         NOT NULL,
    `Time`   TIME         NOT NULL
);

CREATE TABLE `consumergroup` (
    `GroupID` INT          NOT NULL AUTO_INCREMENT PRIMARY KEY,
    `Name`    VARCHAR(128) NOT NULL UNIQUE,
    `Amount`  INT          NOT NULL DEFAULT 0
);

CREATE TABLE `consuptiondata` (
    `GroupID`        INT     NOT NULL,
    `Date`           DATE    NOT NULL,
    `Hour`           TINYINT NOT NULL,
    `ConsumerAmount` INT     NOT NULL,
    `Consuption`     DOUBLE  NOT NULL,
    PRIMARY KEY (`GroupID`, `Date`, `Hour`),
    FOREIGN KEY (`GroupID`) REFERENCES `consumergroup` (`GroupID`)
);

CREATE TABLE `forecastdata` (
    `GroupID`        INT     NOT NULL,
    `Date`           DATE    NOT NULL,
    `Hour`           TINYINT NOT NULL,
    `ConsumerAmount` INT     NOT NULL,
    `Consuption`     DOUBLE  NOT NULL,
    PRIMARY KEY (`GroupID`, `Date`, `Hour`),
    FOREIGN KEY (`GroupID`) REFERENCES `consumergroup` (`GroupID`)
);
```

Имя базы может быть любым — его указывают в настройках подключения.

## Архитектура

| Папка | Содержимое |
|---|---|
| `MainMenu/` | окно входа |
| `RoleMenu/` | главные окна администратора, аналитика и энергетика |
| `DialogWindows/` | диалоги: учётные записи, настройки БД, аудит, данные, группы потребителей, ошибки загрузки, потеря соединения |
| `Manager/` | `DataManager` — единая точка доступа к данным, `ForecastManager` — управление прогнозом, `LoginLockout` — блокировка входа |
| `Manager/Worker/` | рабочие объекты в отдельных потоках: работа с БД, разбор CSV, таймер прогноза |
| `Config/` | константы, ключи настроек, структуры строк таблиц |
| `CustomWidgets/` | собственные виджеты |

Все обращения к базе данных выполняются в отдельном потоке и общаются с интерфейсом через сигналы и слоты Qt.

## Сборка

Нужны:
- CMake 3.16 или новее;
- Qt 6 (или Qt 5) с модулем Widgets;
- компилятор MinGW 64-bit — прилагаемая `libbcrypt.a` собрана под него;
- сервер MySQL.

```bash
cmake -B build -G Ninja -DCMAKE_PREFIX_PATH=<путь к Qt>/mingw_64
cmake --build build
```

Или откройте `CMakeLists.txt` в Qt Creator и выберите комплект с MinGW. Сборка проверена на Qt 6.8.3 с MinGW 13.1 (64-bit).

### Драйвер MySQL

Приложение подключается через драйвер Qt `QMYSQL`. В официальной поставке Qt для Windows его нет, поэтому без него подключиться к базе не получится. Нужны два файла:

1. **Плагин `qsqlmysql.dll`.** Он должен быть собран под ту же версию Qt, что и приложение, — минорная версия обязана совпадать (для Qt 6.8.3 подходит плагин от Qt 6.8.x), и тем же компилятором (MinGW 64-bit). Плагин от другой версии Qt или собранный MSVC не загрузится. Собрать его можно из исходников Qt (`qtbase/src/plugins/sqldrivers`) или взять готовую сборку под нужную версию Qt. Файл кладётся в папку `sqldrivers` рядом с программой или в `<Qt>/mingw_64/plugins/sqldrivers`.
2. **Клиентская библиотека MySQL `libmysql.dll`** — 64-битная, из MySQL Connector/C или из папки `lib` сервера MySQL 8.x. Кладётся рядом с `EFS_Project.exe` или в папку, указанную в `PATH`.

Проверить, что драйвер найден, можно в окне настроек базы данных: если `QMYSQL` недоступен, приложение сообщает об этом в отладочном выводе.
